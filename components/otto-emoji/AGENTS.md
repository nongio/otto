# otto-emoji

The emoji picker: a card over the desktop with a search field, category tabs and a grid. Picking an emoji closes the card and delivers it to the window that had the keyboard. It is a Wayland client started fresh from a key binding (`Ctrl+period` in the shipped config) and gone once something is picked. There is no daemon.

- **Layer:** app. Nothing depends on it in normal builds; the compositor's end-to-end test `tests/emoji_typing.rs` uses its library as a dev-dependency.

## Dependencies
- **Internal:** `otto-kit` for the app runner, surfaces, frosting, theme, components, clipboard, focus, accessibility and i18n.
- **External:**
  - From the compositor: `wlr-layer-shell` (an overlay card), `zwp_virtual_keyboard_v1` for typing, `zwlr_foreign_toplevel_manager_v1` to learn which app had focus.
  - `xkbcommon` and `memfd` build the per-pick keymap the virtual keyboard uploads. `laye-rs` and `taffy` lay out the card; Skia draws it.
  - The emoji table is Unicode's `emoji-test.txt`, slimmed into `data/emoji.txt` and baked into the binary.

## Develop
- Against a dev compositor: `cargo run -- --winit`, then `WAYLAND_DISPLAY=wayland-1 cargo run -p otto-emoji`. Arguments: `--auto` (default), `--type`, `--copy`, then an optional starting query.
- `cargo run -p otto-emoji --example preview -- /tmp/emoji "" cat` renders the card to PNGs without taking over a screen. `OTTO_EMOJI_PAN` sets the pan position in the preview.
- `cargo run -p otto-emoji --example type -- "👋🏽"` types text through the picker's virtual-keyboard path into the focused window, to check how a client decodes it. Point it at a nested compositor with a window such as `wev` focused.
- Swipe tuning: `OTTO_EMOJI_PAN_SPEED` and `OTTO_EMOJI_FLICK`.
- Logs: `RUST_LOG=otto_emoji=debug`. Tests: `cargo test -p otto-emoji`, and end to end against the headless compositor: `cargo test --features headless --test emoji_typing`.
- Regenerate the table with `data/regen.py [emoji-test.txt] > data/emoji.txt` (fetches the latest from unicode.org without an argument).

## Where things are
- `src/main.rs` is the picker app: surface, input, delivery, the command line. `src/lib.rs` exposes the parts that need no screen, for tests and the examples.
- `src/view.rs` is the card's scene and layout; `src/data.rs` and `src/search.rs` parse and rank the table.
- Delivery is `src/typing.rs` (the virtual keyboard) and `src/target.rs` (the focused app). Recent picks and the skin tone live in `$XDG_STATE_HOME/otto/`.

## Rules
- `data/emoji.txt` is generated by `data/regen.py`. Do not edit it by hand.
- Typing uploads a keymap with one key per codepoint and taps them in order. `--auto` types into terminals (the `TERMINALS` list in `target.rs`) and pastes everywhere else, because key delivery breaks in Chromium-based apps and Ctrl+V is not paste in a terminal.
- With `--copy` the process stays alive until the pick is pasted or replaced, because a clipboard offer lives as long as the client that made it.
- Do not run the `type` example against the session you are working in: it types into whatever has focus.
